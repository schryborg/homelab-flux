# AGENTS.md

Guidelines for AI agents working on this repository.

## Repository Overview

This repository contains a [Flux CD](https://fluxcd.io/) GitOps configuration for a single k3s homelab cluster.

- **Cluster name:** `homelab`
- **Flux version:** `v2.9.6`
- **Git source:** `ssh://git@192.168.50.22/luke/flux.git` (branch `main`)
- **Bootstrap path:** `./clusters/homelab`
- **Target namespace:** `flux-system`

Flux is bootstrapped into the k3s cluster and reconciles manifests from this repository automatically.

## Repository Layout

```
.
├── README.md
├── AGENTS.md                    # This file
├── infrastructure/              # Cluster-wide infrastructure
│   ├── base/                    # Shared controller and config bases
│   └── homelab/                 # Cluster-specific overlays
└── clusters/
    └── homelab/
        ├── flux-system/
        │   ├── gotk-components.yaml   # Flux controllers (auto-generated, do not edit)
        │   ├── gotk-sync.yaml         # GitRepository + Kustomization for this repo
        │   └── kustomization.yaml     # Kustomize entrypoint for the flux-system dir
        └── infrastructure.yaml        # Flux Kustomizations for infrastructure
```

`gotk-components.yaml` is generated by `flux bootstrap` and should not be hand-edited. Manual edits will be overwritten on the next bootstrap/upgrade.

## Conventions

- One cluster per directory under `clusters/<name>/`.
- Cluster-wide infrastructure (controllers and their config) goes under `infrastructure/`.
- For future application workloads, use `apps/base/` (shared) and `apps/<cluster>/` (overlays); these directories and an apps Flux entrypoint are not present yet.
- Prefer `Kustomization` + `GitRepository`/`OCIRepository` for application workloads.
- Keep sensitive values out of plain YAML; use `SealedSecrets`, `SOPS`, or external secret references.
- Use resource names and namespaces consistently; namespace is usually declared explicitly in manifests.

## Common Operations

These commands assume `flux` CLI and `kubectl` are configured for the homelab k3s cluster.

```bash
# Reconcile the entire flux-system configuration
flux reconcile kustomization flux-system --with-source

# Check Flux status
flux status
flux get all

# Suspend / resume a kustomization
flux suspend kustomization <name>
flux resume kustomization <name>

# Preview what kustomize will build
kubectl kustomize ./clusters/homelab
```

## Safety Rules

1. **Never commit raw secrets.** Use sealed secrets, SOPS, or external secret stores.
2. **Do not hand-edit `gotk-components.yaml`.** Use `flux bootstrap` or `flux install` to update Flux.
3. **Validate manifests before committing.** If `kustomize` is available, run `kubectl kustomize --load-restrictor=LoadRestrictionsNone <path>` to ensure resources build cleanly.
4. **Be careful with `prune: true`.** Removing a manifest from Git will delete it from the cluster on the next reconciliation.
5. **Prefer additive changes.** When adding a new application, create a new directory and a new `Kustomization` resource rather than dumping everything into `flux-system`.

## Adding Infrastructure

1. Add a shared base under `infrastructure/base/<name>/` (e.g. `infrastructure/base/cert-manager/`).
2. Add a cluster overlay under `infrastructure/homelab/<name>/` referencing `../../base/<name>`.
3. Add a Flux `Kustomization` to `clusters/homelab/infrastructure.yaml` pointing at the overlay, using `dependsOn` when one layer must wait for another.
4. Validate with `kubectl kustomize ./infrastructure/homelab/<name>`.
5. Commit and run `flux reconcile kustomization flux-system --with-source` to verify.
